# will_delete.txt — what purgable will delete, and what it will not

Audit of a 1,237-line list of 1,100 unique directory names, against the 40 policies in the shipped default config.

Every name is given a verdict, derived from the policies in `src/config.rs` rather than by hand. If you add a policy, this file needs a new line to match it. The original list is recoverable by stripping the verdict column from the index at the end.

To see the real thing on your own machine:

```sh
purgable mark ~ --dry-run     # writes nothing, prints every candidate
purgable review ~             # only now can anything be deleted
```

`mark` only writes a `PURGABLE` marker file. Nothing is destroyed until you answer a prompt in `review`.

## Summary

| verdict | unique | of list | meaning |
|---------|-------:|--------:|---------|
| **POLICY** | 86 | 98 | a shipped policy matches this name, when its guard passes |
| **PATH** | 84 | 84 | a nested path like `target/debug/deps`: covered by its parent when that parent matches |
| **EXCLUDED** | 293 | 329 | deliberately never matched, reason given below |
| **CANNOT-MATCH** | 45 | 47 | a file, a glob, or a symlink the traversal cannot mark |
| **NO POLICY** | 592 | 679 | no tool in the default set creates this name |
| **total** | 1100 | 1237 | |

**86 of 1100 names can be marked — 40 policies.** A further 84 are nested paths that come along when their parent matches. The other 930 cannot, which is the point: the list was mostly a list of things that should never have been in it.

## What purgable will delete

Each name below is matched by a policy. Most policies also require a marker before they will match: a build-system file next to the directory, or a file only that tool writes inside it. That guard is what stops `linux/kernel/drivers/target` from being treated as Cargo build output.

The exceptions are marked *no guard* below: `.cache`, `.pytest_cache`, `.vite` and friends are dot-directories that belong to no other convention, so there is nothing to tell them apart from and nothing to confuse them with. None of them is a name a source tree would use.

### Nested paths, covered by their parent

84 entries are paths rather than names. `mark` recurses on its own and policies match one directory name at a time, so these are not separate policies: if the first segment matches, the parent covers the lot, because `mark` stops descending at a match.

Whether that guard passes depends on where the path is, which is why these are not simply listed as safe. `.gradle/caches` is matched by `gradle-project-cache` inside an Android project and is never matched at `~`, where it holds credentials.

### Test-run artifacts and browser downloads

evidence of a failing run.

`.cypress`, `cypress/screenshots`, `cypress/videos`, `cypress/downloads`,
`playwright/.cache`, `bootstrap/cache`

### Checked-in application assets in the relevant framework, not…

Checked-in application assets in the relevant framework, not build output.

`public`, `site`, `resources/_gen`, `wwwroot`

`project/target`, `project/project`, `project/project/target`, `project/.bloop`

### Rails storage

`sessions/` holds live session data, so clearing it signs everyone out.

`storage/framework/cache`, `storage/framework/sessions` (x2),
`storage/framework/views`, `storage/framework/testing`

### A project `.yarn` is not all cache

`patches/` and `releases/` are checked-in source, and `releases/` holds the
Yarn binary itself. Only `cache/` and `unplugged/` are disposable.

`.yarn`, `.yarn/cache`, `.yarn/unplugged`

### Not a directory name any tool creates

Mocha has no cache directory; builds go to `out`, `dist` or `.cache`.

`.build-cache`, `.build-cache-dir`, `.mocha-cache`

### Ambiguous

As often a directory of hand-written or committed generated code as a cache.

`codegen`, `.codegen`, `.codegen-cache`

Restoring needs `carthage bootstrap` and network access, and `Checkouts` is a

`Carthage/Build`, `Carthage/Checkouts`

### Buck state

Use `buck clean`.

`.buckd`, `.buck-cache`

Hypothesis keeps an example database of inputs that triggered past failures. It

`.hypothesis`
